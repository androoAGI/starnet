## Findings requiring repair and focused proof

**M1 — An unread oversized skill response prevents bounded connection cleanup.** The root already proved the standalone document path using real local sockets. `exchange-fetch.js:69` rejects declared Content-Length before consuming or cancelling its body. The callback then exits into `withPinned()`'s awaited graceful dispatcher close. That close waits on the unread response, so the caller does not receive its already-known size refusal until the request timer aborts it. Root's valid `egress-oversize-body-original-02.log` records `request -> close-start -> request-aborted -> socket-closed -> close-done -> caller-settled`, with `unnecessaryAbortBeforeRefusal:true`, using `egress-oversize-body-review.cjs`. The first unsuffixed original log used invalid recursive instrumentation and is expressly excluded.

The package-session path is a stronger case of the same defect, source-confirmed here. `dialed(dest,sess,fn)` directly calls `fn(sess.dispatcher(dest))`. A declared-size refusal exits `run()`, whose finally blocks clear both the idle timer and the whole-read timer. The package's finally then awaits `b.close() -> session.close() -> dispatcher.close()` with the body still unread and no remaining fetch timer. An unended/trickling body can therefore hold package cleanup indefinitely. This is introduced ownership debt from moving downloads onto an owned graceful-close/session transport; the size check itself predates the lane.

Repair at the response owner: release/cancel the response body on every refusal path before yielding to graceful close, retaining the original error and existing size/deadline/redirect policy. Do not replace bounded cancellation with a timeout increase or a process-wide dispatcher kill. Required deterministic controls: actual local socket, declared-oversized standalone response and first package-file response (actual session/package API), held-open body, exact size refusal, owned socket/dispatcher closed without waiting for the timeout abort. Keep a valid consumed-body/package success and redirect/error-status cancellation control. The real transport may be substituted only at the allocated local socket edge, as in the lane's existing real-socket test.

**M2 — OAuth header-only and early error paths abandon response bodies after removing their abort deadline.** This is inherited in the pre-lane consumer code, but is within this round's full consumer/close-ownership review. `mcp/oauth.js:getJson` rejects a non-2xx response immediately (`116–117`) without consuming/cancelling its body. `withDeadline` then clears its timer and removes the external abort listener. The OAuth fetch wrapper has already started background graceful `Agent.close()`, which remains dependent on that unread body. Separately, the host's custom connector authorization probe (`index.js:16707`) obtains a Response under `withDeadline`, reads only `WWW-Authenticate`, and never disposes the body; its Accept header explicitly permits an event stream. A server-controlled trickling error/redirect or probe body can keep owned sockets alive after the operation moves on or refuses. This is a resource ownership/availability finding, not an SSRF or token-forwarding bypass.

Required controls: use actual OAuth discovery plus the production header-only probe boundary with an allocated synthetic server. Return a non-2xx PRM response with an unended body, and a probe response whose pointer header is usable but body remains open. Prove the expected refusal/pointer processing, no followed redirect, and prompt owned socket/dispatcher release after the caller stops reading. Also retain a normal JSON success. Token/DCR error paths currently consume `res.text()` inside the deadline; do not conflate those with the two abandoned-body branches or cancel a successful Response before its legitimate consumer reads it. Repair the actual response-owning callers (or an equally explicit lifetime contract), not the general wrapper by immediately destroying every returned Response. No runtime proof of M2 was run in this review.

## Reviewed security properties

No additional blocker or major SSRF bypass was found in the following source paths. These are source conclusions, not claims of exhaustive network proof.

- `safe-egress.js` uses the URL parser before classification; normalizes brackets, case and root dots; rejects private/intranet/metadata names and the approved IPv4/IPv6 ranges. Embedded mapped, translated, compatible, NAT64 and 6to4 addresses are classified by the embedded IPv4. Malformed literal/DNS answers refuse. Mixed public/private answers refuse before a dispatcher is created; DNS errors do not become a safe answer.
- A Destination is privately minted and frozen, its URL getter returns a fresh object, and its address list is deeply frozen. The pinned lookup never asks DNS again, supports Node's `all:true` callback shape and family filtering, and refuses a different hostname. Every validated address remains available for family fallback. Literal URLs require no DNS pin. Test-only null lookup and custom transport factories are not supplied by the production composition root.
- Web direct fetch/request validates each manual redirect, pins that hop's own answer, and prevents a caller-supplied href from moving to a different origin. Stored-secret header slots are tracked by actual substitution and stripped on scheme/host/port origin change, alongside the credential-name denylist. Host-attached query authentication is not reattached on later hops. Remote redirect refusals remain untrusted; caller-owned URL refusals alone receive the host-authored mark. External response content remains fenced/redacted.
- The owned browser's production launcher supplies the validating proxy and disables the loopback proxy bypass. HTTP, CONNECT and WebSocket proxy paths validate before dialing; CONNECT preserves end-to-end TLS/SNI. Pending DNS callbacks check closing/destroyed ownership before creating an upstream. Proxy cleanup destroys only its own tracked sockets and agent. The explicit owned dev-server origin exception remains distinct from public browsing.
- Connector OAuth requires public HTTPS with no embedded credentials through the fetch wrapper and always forces manual redirects. The separate metadata URL check now delegates to the same classifier and fails closed without the sidecar module. The system browser authorization endpoint receives prevalidation only; this review does not claim that the external browser is itself a sidecar-pinned transport.
- Skill documents and package files use the same public-HTTPS policy for every hop. Session caching retains only validated answers, refuses destinations from another session, and refuses resolution/dial after close. Redirect/error responses already have a discard path; M1 identifies the uncovered size-refusal path. Package path/byte/request/depth limits and installed-market authority are not lifted by this review.
