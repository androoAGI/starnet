# StarNet v0.15.0

Deleting a chat now forgets it across the station's records (limits below). A reviewer's BLOCKED holds a job for you to decide, and in a direct chat a message you send mid-run steers that run. Image spend gets caps, and a rewind never deletes through a link. Update, then open StarNet once: the first save moves your station file to format v7 and keeps your old file for 30 days. Going back to 0.14.2 takes manual steps, below.

## Upgrading, and going back

- **The first save moves your station file to format v7, and keeps a copy of the old one for 30 days.** Format v7 saves each chat's history by reference to the transcript the station keeps, instead of copying every message into the save. Before the first v7 save replaces the station file, StarNet copies the old file once to `agent.save.pre-history-ref.json`, beside it in the station folder (on Windows `%APPDATA%\ai.skynet.harness\workspaces`). If the disk has no room for that copy, the replace goes on only when the old file survives as `agent.save.json.bak`; otherwise that save is refused and nothing is replaced. The copy goes 30 days after it was made, once the new format has read back. It holds every chat, so a chat you delete is cut out of it too.
- **Going back to 0.14.2 brings back your station file from before the update, but you put it back by hand.** 0.14.2 can't read format v7: it stops at a "saved format v7 · this build reads up to v6" screen and leaves the file untouched. To go back on Windows: (1) quit StarNet completely; (2) in the station folder (`%APPDATA%\ai.skynet.harness\workspaces`; the desktop app always uses this folder), copy `agent.save.json` somewhere safe and move `agent.save.json.bak` out of the folder; (3) copy `agent.save.pre-history-ref.json` to a new `agent.save.json`; (4) delete the app window's own storage, the folder `%LOCALAPPDATA%\ai.skynet.harness\EBWebView\Default\Local Storage`: it holds a v7 copy of the save, which 0.14.2 checks first and would stop at the screen above, and deleting it also clears what the window keeps only for itself (layout, dismissed hints and a few window-only records); (5) install 0.14.2 and open it. Anything you wrote after the update is not in the old file; the copy from step 2 is the only record of it. This version also moves a chat bot's own provider endpoint off its channel record, and 0.14.2 does not read where it moved it to: after going back, a bot you connected with its own endpoint runs on the station's endpoint for that provider until you connect it again in 0.14.2. We rehearsed the station file: 0.14.2's own station code read the kept file, extra `keptAt` field and all, with every chat from before the update. On macOS, ask us first: we have not mapped where the window keeps its storage there.
- **After you update, open StarNet once.** The page is what brings a version 6 save up to v7. Until it has saved again, anything that runs with the page closed (routines, channel bots and other services that route through your floor) refuses to run, in these words: "the saved floor is waiting for a migration (open StarNet once to bring it up to date); routing is held until it is readable". The refusal costs nothing. Open the app, wait for it to save, and they run again.

## Still off in this release

- **The world-idle renderer is behind a developer flag, and is off.** The code is in, with the quieter idle floor and the wake on a message that starts no run, but nothing changes a single draw unless the flag is set (`?idleRenderer=1`); there is no switch for it in the app. The quiet-window measurement and the look comparison are still to do before it is on by default.
- **The turn-identity final switch (C13) is not in this release.** It follows a soak. Today the page's history window still runs in shadow, comparing by id and recording counts and kinds, never words, while merging, replay and display already use ids.

## Held jobs and gates

- **A reviewer's `VERDICT: BLOCKED` now holds the work at its gate** (GitHub #122). Before, BLOCKED read as "not approved", the work went round for more paid passes, and once the passes ran out it shipped as DONE, unapproved. Now it stops with no further hops and nothing reaches the OUTBOX, whichever word the gate waits on and at any pass. Every spelling a model puts on its VERDICT line counts (`**VERDICT:** BLOCKED`, `VERDICT: \`blocked\``, `VERDICT: do not ship`); "Blocking issues: none" is not read as BLOCKED. A FILTER between a reviewer and its gate can no longer carry a blocked job past it. Reviewers are now told BLOCKED is an answer they can give.
- **A reply with no usable verdict holds the job too.** A verdict gate used to read a missing, empty or unknown verdict as "revise" and spend five more paid passes. It now holds for you with zero further spend, at any pass.
- **A held job waits for you, and survives a restart.** A job held at its gate keeps its saved walk on the record WORKFLOWS reads. A restart finds it still held and makes no model call. APPROVE resumes from the saved step, once, and a second press buys nothing. SEND BACK carries your note to the writer for another pass. STOP on a held job ends it, and nothing more is spent. A held job is not listed in DELIVERABLES until it is approved. While E-STOP is on, APPROVE and SEND BACK are refused with the reason and the job stays held; STOP still ends it.
- **A held job can always be stopped.** A refused APPROVE (the crew wasn't back, say) used to keep its receipt for good, so a UI or script that kept retrying could fill the receipt list until even STOP couldn't be recorded. Refusals are now capped to the newest, and STOP still takes the job.
- **Every line stop says why, in one way.** A stage that hit a spending or step limit, or whose reply the provider cut, used to stop the line as "editor failed: hit a spending limit". A stop now carries one named reason (hop limit, spending limit, day limit, stage unfinished, stage failed, empty stage, blocked, refused and so on), and the chat note, the routine's record and the step-through test all read it.

## Routing from the saved floor

- **Routing comes from the saved floor, not from whatever the page last posted.** Chat channels, routines, loops, line jobs and the other things that run without the page route through the work line saved in your station file. There is no switch. A `POST /api/routing` is only a question about the saved floor: a plan that doesn't match it changes nothing and answers "pending". A page's post can no longer widen the tools a headless run gets: the room comes from the saved station.
- **When the saved floor can't be proved, nothing runs from it, and the refusal costs nothing.** A floor that is corrupt, unreadable, from a newer StarNet, not vouched for, still being saved or waiting for a migration is refused in words ("the saved floor is corrupt; routing is held until it is readable"), wherever you meet it: a chat reply, a routine's blocked row, Run Now, a line's stop. The model is never called, no queued item is counted as an attempt, no loop is paused for it. When the file reads again, the same work runs, with no restart.

## Sessions and history

- **A station's chats are saved by reference.** In format v7, a chat's history names runs of rows that the station's transcript holds. In our measurement, 10,000 chats of three turns took 19.8 MiB in the old format, over the save's 16 MiB cap, and 5.8 MiB in v7; 12,000 such chats (23.7 MiB) were refused before and are taken now. Once the station has confirmed a chat's rows, three turns add about 25 bytes to that chat's entry in the save, and three turns with an attachment each about 70. Merging a second window, restoring a preserved save and reopening a chat all read packed history as faithfully as inline, and a row the station can't return is never guessed or dropped.
- **Files and pictures in a message are rows of their own.** A text file you attach used to be stored as part of your own words, so a third party's document was later quoted as "the Commander's words" and tainted every later run. Now your row holds only what you typed, and each file or picture is its own row beside it (with its name, type and size). A file's or picture's contents go to the model with the message that attaches it and the one after; later messages carry a note naming the saved file instead. The newest picture in the message you send is always sent.
- **Taint from an attachment fades when its bytes leave the view.** A summary of a conversation that held the attachment keeps the attachment's mark; one of replies only does not.
- **A long chat is summarized once, not on every send.** Before, every send past the fold line summarized the same range again (14 paid summarizer calls in the 14 sends after the line in our probe). A paid summary is now kept with the rows it stands for and reused byte for byte while it is still true.
- **A message queued with photos sends them with it.** It takes its words and files at Enter and stands in its own chat's queue; a stalled upload no longer locks the box, and a held message spends nothing until it goes.
- **A session lost on an old save's merge is fixed.** 0.14.2 could drop a newer session when an older save was merged in. Saves now wait on journals left unread, and a page alone in its browser opens its journal without the fixed 250 ms wait.
- **A whole-station recovery bundle** (GitHub #119). SETTINGS › APP & BACKUP › RECOVERY BUNDLE saves the station from the running app into Downloads, never overwriting, with an honest report of anything skipped, repaired from a backup copy or left torn. A restore is a command-line step with StarNet quit (`station-recovery restore`); restoring over your station keeps the old folder beside it as a rollback, and nothing acts on its own afterward: routines, grants, loops, triggers, connectors, channel bots and queued reports all come back off until you turn them on. A locked connector store is left out and reported, not thrown.

## Deleting a chat forgets it everywhere

- **A deleted chat's words leave the stores derived from it,** apart from those under Known limits. One registry names each place the station keeps words drawn from a chat (notes and memories, interests, staged drafts, verdict packets, task briefs, goldens, study proposals, deliverable rows, night-shift drafts, quests, overseer threads, worker records, uploaded files) and removes them when the chat is deleted. A census test fails if the station gains a store that is neither purged nor listed with a reason it is kept. Deletes made on 0.14 are caught up once, at the first start. That start also clears machine-made items from before your most recent such delete that cannot show which chat they came from: open generated quests, staged scout and night-shift drafts, night-shift jobs not yet built, pending north-star suggestions and staged quests, the last away briefing and the Commander dossier block. The next refresh makes them again from the chats you kept. Nothing you wrote is removed, and finished or dismissed quests and built jobs stay. For a chat deleted before 0.14.0, its transcript, recall and titles stay forgotten, but the stores derived from it are not purged.
- **Words a run took from a deleted chat go too.** If another chat's run read a chat with `recall_conversation` and quoted it, deleting the source removes those words from display, recall and replay, and the run record names the session it read. After a restart, nothing comes back. A file such a run wrote from what it read leaves the chat and the deliverables library too. The file itself stays in the agent's workspace, like other delivered work.
- **A delete reaches the kept v6 file and the undo rows.** The `pre-history-ref` copy, a chat's restored copies and its rows in the undo checkpoint are cut at the same time. A file you uploaded to a deleted chat is removed, unless another chat still names it (a /branch copy or a re-send keeps the file it shares), and new restore points leave uploads out. Restore points made before this update can still hold an upload. If you send a file uploaded before this update again in a chat, then delete that chat, and one of the agent's older restore points holds the file, that agent's restore points are replaced by one of its workspace as it is now, and you can no longer rewind it to an earlier point.
- **A held job whose chat was deleted ends, with its walk dropped,** so a decision on it finds nothing waiting. A message's attached file goes with its deleted session.

## Messages sent mid-run steer the run

- **Send a message while an agent works and it joins the running task.** In a direct COMMS chat, an ordinary message reaches the confirmed run at its next model boundary, in order and with its files, and is tried again if the run is briefly too busy to take it. The queued "send now" pill is gone. Stop is still separate and immediate. A receipt means the message was received, not that the agent acted on it. `/queue` still asks for a later turn, and group chats and delegated workers keep their own paths.

## Honest run outcomes

- **Every run end reads one outcome on every surface.** The station's bookkeeping, `/v1`, the MCP bridge, ACP, the terminal, the phone, work lines, channels, routines, the crew, COMMS and the floor take the word, the tone and the count from the same record.
- **A run ends exactly once, and one that threw books what it spent.** A `/v1` chat whose host failed after its start used to answer 502 while the floor saw the run start and never end, and a run that threw after a priced call wrote a history row of a known $0.
- **STOP and E-STOP reach every live run.** A queued `/v1` chat, a hub turn or a run held at the provider can be stopped by its id, and the phone, the stop and steer routes and the reconnect snapshot read the same list.
- **One provider and model per agent, on every entry point.** Chat, routines, loops, channels, the CLI and `/v1` now resolve the pair the same way. An explicit choice that names a provider the station doesn't know is refused, never borrowed onto another provider's key; `/v1` answers 503 `model_not_configured` or `provider_not_configured` before any run starts.
- **A long research run no longer goes blind on the tool-output budget.** The budget could empty below the fold line, so every later result became a receipt and the run could never recover. Once the budget is spent, results of up to 2,000 characters still arrive whole, up to four a turn, and a result no longer than its receipt always does.
- **A silent local model server gets one request, not seven.** A server on this computer or this network (LM Studio, vLLM, llama.cpp) that stays silent through its wait, 300 seconds by default, ends the turn with a `local_timeout` naming the host, the phase and the wait, instead of sending the prompt again. If another StarNet call is open on the same server, the request is sent once more first. `SKYNET_LOCAL_CONNECT_TIMEOUT_MS` and `SKYNET_PROVIDER_IDLE_MS` change the wait.

## Security and egress

- **One boundary decides where the station may connect.** Web requests and fetches, the browser and its proxy, connector sign-in and skill downloads all use one table of destinations and one DNS answer per hop, dialed pinned. This closes private IPv4 addresses spelled as IPv6 (`[::127.0.0.1]`, NAT64, 6to4), `metadata.goog`, multicast and reserved ranges that some paths let through, a connector sign-in that refused every IPv6 address written in its URL (public ones too), and a skill download that resolved the name twice.
- **The shell tells a local program from a GUI by its file, and no wrapper vouches for it** (GitHub #167, #163). `git.exe status` and `powershell.exe -File a.ps1` run where they were refused for being spelled `.exe`; a GUI program, a missing file or anything unproven is still refused, with a reason. `cmd /c` and `powershell -c` re-read their text, so what they run next can't be proven and gets no vouching. cmd's own switches, the bodies of `if`, `for` and `forfiles`, and bare names found along PATH are now judged the way they run. Text typed into a live terminal that the guard can't vouch for is refused, REPL code included. This is a closed list of respellings, not a claim that none is left.
- **A key you remove or replace stops the runs using it.** A run in flight stops at its next call once its key is removed or rotated in Settings, not mid-stream. On the desktop, removing a key now removes the keychain copy the app starts the station with, so Run Now, scheduled fires and `/v1` stop using it. A refused key no longer rotates onto another account's.
- **A chat bot's own key lives in one store.** A channel record holds a reference, so a rotation is followed and a replaced key doesn't linger in a backup until the next save. A change to a bot's own key lands with the record that names it. On the desktop app a bot's own key is kept only while the app runs, as before, but after a restart the bot no longer runs on the station's key or quietly stops: it is refused, with the reason in its status line, until you reconnect it with its key, or with no key to use the station's.
- **`browser.upload` gives the file to the input the page opens** (GitHub #104). A ref on an upload button used to go to the nearest file input by position, so a decoy input could take the file and read back as selected while the page's real input heard nothing. Now an upload control is clicked with the file chooser caught, and the input the page opens gets the file. A submit button, a link, a disabled control or any name not plainly an upload is never clicked; it gets the file only when one file input is nearby, as before. A file the input's accept list excludes is refused, and the receipt says when the page did not react. Tested on fixture pages, not on a live site.

## Spend and image caps

- **Images of unknown cost are capped** (GitHub #164). An image with no price from the provider booked $0, so no dollar limit could stop it: 50 images passed a $0.35 cap. A run family now stops at 10 such images, and the station stops at 50 in any 24 hours, counted from the spend log so a restart keeps the count. The refusal comes before any request and says when room returns. A damaged log line refuses rather than reading as zero. A ChatGPT-plan image takes the Codex route, which does not ask.
- **A receipt says "cost unknown" instead of $0.** An image's receipt gives the provider's figure or UNKNOWN, spend rows mark it, and the run recap says "cost unknown" or "at least". No price is invented, so one image can still pass a limit that has room left.
- **A run that falls back to a key meets its run cap on its next image.** An unmetered run moved onto a key kept the stale "unmetered" flag and skipped the cap.
- **One governor admits every paid call.** Nine call sites each decided for themselves, and a check that threw was read three ways. A throwing check now refuses, and says so; the skill curator is covered; a ChatGPT plan, which spends no dollars, is no longer stopped by a dollar cap (its SET IT UP FOR ME and night shift used to refuse on it).
- **One torn spend-log line no longer blocks every run.** A torn line, or a run interrupted days earlier, used to make every limit refuse every paid run until settled. Each open receipt is now an item with a bound, or names its one-click exit.
- **Each compaction attempt is counted and admitted** against your limits.
- **A ChatGPT limit message says the plan is used up only when the numbers say so** (GitHub #158). A wait past 15 minutes, a meter at 100%, or a plan code reads as the plan; short waits say how long; room on the meters is never called a spent allowance. We still don't know which refusal the reporter hit; the message now carries the provider's code and meters, so the next report will settle it.
- **Background passes on a sign-in route stop at a 24-hour token ceiling** (GitHub #105). Background passes (reflection, skill review, quest look and the like) on a subscription route stop at a ceiling per route over any 24 hours, and the Memory panel's reflection switch reads "ON, PAUSED ON <route>" while it holds. Local models have no ceiling, 0 turns it off, and your own runs are never limited by it. REFRESH QUESTS still runs past it.

## Delivery and channels

- **A routine's reply joins a chat's history only after its delivery is on record.** When a routine delivers to a chat app, its reply is written into that chat's history only from the saved delivery receipt, and the receipt is checked first, after a restart too.
- **Chat apps read one canonical history.** Telegram, Discord, Slack, Matrix and Signal replies read the chat's canonical stream, and the chat store reads, keeps and replaces through the station's one persistence path, so a busy file is a typed refusal, not a lost write.
- **A work line stage replays its chat's words, never another agent's tool calls.**
- **A text export is confirmed before it says saved.** An exported text file shows a receipt for its destination, and ROUTINES, LOOPS and CONNECTORS announce only what the station confirmed.

## Desktop install integrity

- **A damaged install names its file before the engine starts.** One file of the install being empty or quarantined used to kill the engine with "makeShellTool is not a function" and nothing naming the file. The desktop app now checks every code file against a manifest of sizes and hashes built in, and names what's wrong.
- **One web-engine floor.** On a healthy Mac with Safari 16.0, every copied report said "web engine: TOO OLD" and one missing non-critical file showed "STARNET NEEDS A NEWER macOS". The floor is declared once and every check uses it.
- **Every station script is accounted for at boot,** and the page's verdict reaches `startup.log`.

## Scheduling and reliability

- **One clock for routines.** Every readout of when a routine runs next now comes from one projection: no next time while scheduling is off, halted or damaged, and stored schedules are never rewritten by reading them.
- **A plugin that crashes during its start window can't wedge the restart.** Its timer used to take over the restart, and a guard plugin's veto was silently off.

## Rewind safety

- **A rewind no longer reads, writes or deletes through a link.** Git for Windows walks a junction as a plain folder, so before this a junction pointing outside the workspace was captured, and a rewind could delete the real files behind one. One boundary now handles every capture; a rewind refuses before touching anything if it would write or delete through a link, below a clone or over a gitlink, and a name Git and the file system read differently is refused. A folder swapped for a link in the instant between the check and Git's read is still followed.
- **A rewind never deletes a file no capture took,** and it refuses what it can't undo. It lists what its reset will remove before it commits, so its undo can restore it; a file in use refuses before the commit.
- **A refused call leaves no checkpoint.** A checkpoint waits for its call's admission.

## Station designer

- **Your agent can design a whole station.** It can pick a palette, start from a prebuilt station, plan a heart and a dressed main room, and read a design review. Rooms are composed in groups with a back-wall rhythm and their own light. There are seven new floor plans: axis, enfilade, colony, campus, pinwheel, court and terrace. The plan card names the palette; added rooms follow the station's plan and palette; and a tidy of the main room keeps every moved piece reachable and inside the room.

## Token efficiency

- **Conversation caches are kept.** Learned state, the dossier and goal blocks sit after the cached prefix instead of changing it, so two runs of one routine can share it; background token spending is admitted one at a time; and a queued quest refresh keeps its provider admission and the pause that governs it. We claim no saving beyond one probe on one call.

## The terminal FLOOR

- **FLOOR in the terminal is faster.** It keeps its picture and draws again only what changed, the Sixel encoder sorts once per band (about 12 ms, was 240 ms), and an idle agent sits at its own desk for a while instead of standing in front of it, then moves to a free spot. In our measurement in a maximized Windows Terminal the floor went from 2.3 frames a second on screen to 9. Your terminal may differ.

## Sound and speech

- **Separate switches for the hum and the heartbeat.** SETTINGS › LOOK & SOUND has BACKGROUND HUM and HEARTBEAT switches. Turn them off and keep TERMINAL AUDIO on for clicks and completion chimes. Existing choices carry over, TERMINAL AUDIO is still the master mute, a running hum fades out, and the choices are in station backups.
- **Speech goes through one ladder.** The desk, Live, the paired device and `voice_generate` used to each walk their own engine order and cut text four ways. They now go through one planner, one retry rule (transient errors only) and one sentence splitter, and a reply stays with the engine that spoke its first sentence. Each surface keeps the starting engine and spend settings it had before.

## Known limits

- **A deleted chat's raw tool results and checkpoint copies stay on disk.** They are never shown: tool and process output saved in `<agent>/.output` has no purge, and an agent's restore points keep delivered work files. A chat-app conversation's history files from before this update (the channel store's `channels/<agent>.history.json`, with its `.bak` and legacy-hops copies) are not reached by a delete. The journal of an interrupted run stays until you resolve it, though a run that began in or read a deleted chat is never offered or continued. A deleted chat can also sit in the previous generation of the station save (`agent.save.json.bak`, ids and titles only under v7) until the next save, and in recovery bundles and rollback folders you made yourself.
- **A held line job in a store the station will not rewrite keeps its words.** If a store has a duplicate or future-version record, StarNet preserves the original, notes it and goes on with the rest of the purge.
- **A copy of a quoting reply keeps its words.** A chat that copied another run's reply, which had quoted a deleted chat, keeps those words after the delete.
- **Some uploads stay after a delete.** Deleting a chat keeps an upload if a damaged transcript line may name it, if one of the transcript's files is missing, or if another program has the file open at that moment. The station's log usually says so, but not always. If the disk refuses to read a transcript file, deleted chats' uploads wait until it can be read again. A file sent from a restored copy of a chat stays when you delete that copy. An upload from a chat you deleted on 0.14 stays too, because nothing names it any more.
- **Link safety in the ssh and remote checkpoint engine is argued, not tested.**
- **A huge station's save is about 5.8 MiB at 10,000 chats,** most of it the per-chat session record.
- **The shell refuses some legitimate forms:** `Start-Process -NoNewWindow` inside PowerShell (use `shell.exec` with `background: true` instead), a `forfiles /c` command that names a bare program (such as `forfiles /c "hostname"`), and PowerShell path-like heads (`sub\tool`).
